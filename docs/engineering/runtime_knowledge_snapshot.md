## 5. Runtime Overview
The ClipForge Runtime Knowledge domain represents the observable, governed execution environment of the platform. It encompasses the structured definition of entities, capabilities, contracts, and lifecycle stages without implying specific underlying implementation constraints or prescribing runtime execution behavior.

## 6. Runtime Vocabulary
- **Runtime:** The execution environment and systemic governance layer encompassing all operational components of the platform.
- **Capability:** An observable, governed functional ability exposed by the Runtime.
- **Service:** A defined unit of functionality managed within the Runtime boundary.
- **Contract:** A formal agreement specifying expected inputs, outputs, and behaviors for a Service or Capability.
- **Interface:** The observable boundary through which a Service or Capability is accessed.
- **Provider:** An entity responsible for fulfilling a specific Capability or Service within the Runtime.
- **Context:** The state and environmental information passed through the Runtime during execution.
- **Policy:** A formal rule governing Runtime behavior, execution, or access.
- **Pipeline:** A defined sequence of Runtime operations or capabilities.
- **Lifecycle:** The governed stages of existence for a Runtime entity (e.g., initialization, execution, termination).
- **Governance:** The structured rules, authorities, and policies managing the Runtime ecosystem.
- **Runtime Truth:** The principle that every Runtime statement must be directly supported by approved Runtime Knowledge, with nothing inferred, estimated, assumed, or invented.
- **Runtime UNKNOWN:** The explicit designation for any Runtime element or behavior that is not explicitly established, ensuring that unknown information is never replaced with inferred information.

The Runtime Vocabulary established in this document becomes the canonical terminology for all Runtime Intelligence artifacts generated during Sprint 6A.4. No terminology drift is permitted.
