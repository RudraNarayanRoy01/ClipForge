## F. Application Audit
The Application layer largely correctly delegates to Domain interfaces (`ILLMReasoningEngine`, `ITranscriptionService`), which are fulfilled by Runtime Adapters (`RuntimeReasoningAdapter`, `RuntimeTranscriptionAdapter`).
However, Application DI Composition (`IntelligenceModule` and `InfrastructureModule`) directly injects configuration into Concrete Providers and wraps them for the Runtime, depriving the Runtime of the ability to make configuration-based routing decisions.

## G. Runtime Audit
The Runtime (`ExecutionEngine`, `RuntimePipeline`, `PlanningContext`) currently defines abstract preferences (e.g., `locality_preference`, `cost_preference`) but consumes NO explicit configuration regarding actual models, devices, or timeouts. Because it lacks access to these configurations, it is unable to own the execution decision.

## H. Provider Audit
Concrete providers (`OllamaProvider`, `WhisperTranscriptionService`) accept global configuration objects (`AISettings`, `TranscriptionSettings`) in their constructors.
They read these objects directly during execution to make hard decisions about which model to load, which device to use, and when to timeout.
This means Providers are acting as secondary Runtime decision engines, governed entirely by static configuration.

## I. DI Audit
In `backend/src/bootstrap/modules/intelligence_module.py`:
```python
def create_provider(c: Container) -> IAIProvider:
    return OllamaProvider(ai_settings, c.resolve(httpx.AsyncClient))
```
In `backend/src/bootstrap/modules/runtime_module.py`:
```python
llm_provider = container.resolve(IAIProvider)
llm_mechanism = LLMExecutionMechanism(llm_provider)
```
Configuration enters the DI container, creates a concrete Provider, and is passed opaquely into the Runtime as an execution mechanism. The Runtime has no knowledge of what model `OllamaProvider` will execute.

## J. Environment Audit
Relevant Environment Variables:
- `OLLAMA_MODEL`
- `TRANSCRIPTION_MODEL`
- `TRANSCRIPTION_DEVICE`
- `AI_TIMEOUT_SECONDS`

Ownership Flow: `ENV` -> `Settings` -> `Provider` -> `Execution`.
This is an architecture bypass. The environment variables are not Runtime inputs; they are directly governing concrete provider execution.

## K. Timeout / Retry Audit
- `ai_timeout_seconds` is owned and enforced by `OllamaProvider`.
- `ai_max_retries` is configured but completely unused.
Both conceptually belong to the Runtime's reliability orchestration, but currently exist either in the Provider or nowhere. Reliability redesign is deferred to 6C.4.

## L. Resource Configuration Audit
`transcription_compute_type` is currently a configuration setting read by the `WhisperTranscriptionService` to dictate hardware limits/precision. It acts as a hardcoded constraint in the Provider rather than a Runtime resource decision.

## M. Test Configuration Audit
`backend/tests/integration/runtime/test_transcription_execution.py` uses `monkeypatch.setenv("TRANSCRIPTION_MODEL", "tiny")` to alter provider configuration. While isolated, this confirms that testing must bypass the Runtime and mutate the environment to affect execution strategy. Any test isolation issues surrounding this belong to 6C.4.3.

## N. Duplicate Configuration Audit
There are no major conflicting configuration sources within the models themselves, but precedence is simply: `BaseSettings default` <- `.env file` <- `Environment Variable`. The ambiguity lies in who owns it, not multiple conflicting objects.

## Q. Candidate Corrections
1. **Remove Configuration from Providers:** `OllamaProvider` and `WhisperTranscriptionService` should receive their execution parameters (model, device, compute, timeout) directly from the `ExecutionWorkload` passed by the Runtime.
2. **Inject Configuration into Runtime:** The Runtime Composition or `PlanningContext` / `ExecutionIntent` must receive the configuration preferences from the Application, allowing the `RuntimePipeline` (or `TargetSelector`) to embed the selected model and device into the `ExecutionTarget`.
3. **DI Update:** Stop injecting `AISettings` and `TranscriptionSettings` into the concrete providers.
